Integration framework: Assembly/Relay

3 October 20262 min read

Assembly/Relay is an integration framework for describing synchronous workflows. It brings components together and makes their context and event connections explicit.

The framework has three key concepts:

  • Assembly is a collaborative group of components, each with its own responsibility and access to the context it needs. Components contribute state and services to the assembly's shared context.
  • Relay adds a bidirectional pipe topology and synchronous event connections between components. Requests travel forwards and responses backwards, with each handler controlling further propagation.
  • Delegate provides typed callback interfaces for connecting components outside the Assembly/Relay ecosystem, including adapters that bring external events into a workflow.

The test suite provides a first introduction to using the framework. Later, actual production components will show how these ideas work in practice.

The implementation comes from my earlier trading-platform project. The ideas draw on my experience at Laplace Research and, before that, on work across various financial IT systems.

I see the framework's conceptual grandfather in the Transaction Script pattern, described by Martin Fowler in Patterns of Enterprise Application Architecture. It organises the business logic for a request as a linear workflow consisting of mid-sized building blocks. Assembly/Relay develops that idea through collaborating components, explicit context and synchronous event flow.
