Building Nomisma

Packaging and distribution

5 October 20262 min read

It might be too early to talk about distribution at the very beginning of the project. Still, the question of how to deliver the product is too important to put off because it affects many development decisions.

For instance, the trading platform might be distributed as a prebuilt library with C++ headers, shared objects and API docs, perhaps packaged in the formats used by popular OS distributions. In that case, I need to think about what the API should be, which platforms to support and how to organize CI/CD for multiple builds and packages, even if I target only one platform at first. Those are questions any mature product development team should have answers to. Nomisma Labs, however, is still new.

Here are the principles I'm following at this stage.

  1. Core platform development is the priority.

    Putting the platform to use and deciding how to deploy the applications built on it are secondary goals.

  2. The API of every component should be clear.

    Even if the package boundary is not yet well defined, the API shows where that boundary should be.

Distribution targets users at two opposite ends of the spectrum.

  • A core platform developer.
  • A trader with no programming experience, armed with AI.

Other cases will be covered later or as needed.

This gives me two packaging options.

  1. Source code distribution. Every component is licensed as "open source" or "source available" and is accessible via GitHub.
  2. Some components will be built as Python wheels so users can simply import the Python module.

All supporting build and packaging tooling will be part of the cmake_template toolchain.
